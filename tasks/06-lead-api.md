# 06. API `POST /api/lead`

**Приоритет:** P0 · **Оценка:** 60 мин

## Решение по хранилищу (ЗАМЕНА исследования)
JSON-файл не подходит: на Vercel ФС read-only, а в serverless нет общего состояния. Выбираем **Upstash Redis** (Vercel Marketplace, free tier): дедуп через атомарный `SET key NX EX 600`, заявки в list/hash. Обоснование — в README. Альтернатива: Turso/Neon.

## Подзадачи
- [ ] `src/app/api/lead/route.ts` (runtime nodejs), `try/catch` + `console.error`
- [ ] Парсинг и повторная валидация через общую Zod-схему; 400 с понятными ошибками по полям
- [ ] Нормализация телефона до сохранения
- [ ] **Дедуп:** ключ `lead:dedupe:<phone>`, `SET NX EX 600`; повтор → 200 `{status:"duplicate"}` (не 500 и не вторая запись)
- [ ] Сохранение: id, createdAt, имя, телефон, интерес, комментарий, attribution (см. 07), user-agent
- [ ] Если сохранение упало — удалить ключ дедупа, чтобы повтор был возможен; ответ 500 с понятным сообщением
- [ ] Honeypot-поле + простой rate limit по IP (Redis `INCR`+`EXPIRE`)
- [ ] Лимит размера тела, экранирование при выводе в Telegram
- [ ] Same-origin проверка (Origin header) вместо полноценного CSRF — публичный JSON API без cookie
- [ ] Просмотр заявок для менеджера: Upstash console + Telegram (отдельной админки не делаем)

## Критерии приёмки
- Два одновременных запроса с одним номером → одна запись.
- Тот же номер через 10 мин → новая заявка.
- Невалидный номер → 400.
