# content-and-data Specification

## Purpose
Обеспечивает хранение и предоставление структурированных данных сайта: продуктов, контактной информации, текстов контента и оптимизированных изображений.

## Requirements

### Requirement: Система предоставляет данные продуктов

Система SHALL хранить информацию о кофейных продуктах с полными названиями, ценами, весом (для сортов) и вкусовыми профилями.

#### Scenario: Структура данных продуктов
- **WHEN** модуль `products.json` импортируется
- **THEN** структура соответствует схеме ProductSchema: сорта (coffee) с полями id, name, description, price, weight, roastLevel, notes, recommendedFor; дрип-пакеты (drip-pack) с id, name, price, quantity; подписка (subscription) с id, name, price, period, includes; значения: "Эфиопия Иргачеффе" (id: "ethiopia", 32 BYN, 250г, light, ["цветочный", "бергамот"]), "Колумбия Уила" (id: "colombia", 29 BYN, 250г, medium, ["карамель", "красное яблоко"]), "Бразилия Серрадо" (id: "brazil", 26 BYN, 250г, medium-dark, ["орех", "шоколад"], "эспрессо"), "Дрип-пакеты ассорти" (id: "drip-pack", 18 BYN, 10 шт), "Подписка на кофе" (id: "subscription", 54 BYN/мес, period: "месяц", includes: ["2 пачки по 250 г", "Бесплатная доставка"])

#### Scenario: Получение продукта по существующему id
- **WHEN** вызывается `getProductById('ethiopia')`
- **THEN** возвращается "Эфиопия Иргачеффе" (32 BYN, 250г, light, ["цветочный", "бергамот"])

#### Scenario: Получение продукта по неизвестному id
- **WHEN** вызывается `getProductById('unknown')`
- **THEN** возвращается undefined

#### Scenario: Валидация данных продукта
- **WHEN** `pnpm build` запускает скрипт `scripts/validate-data.ts`
- **THEN** каждый продукт проходит через ProductSchema.parse; при несоответствии сборка завершается ошибкой

### Requirement: Система предоставляет данные сайта

Система SHALL хранить контактную информацию, часы работы, условия доставки и самовывоза.

#### Scenario: Структура данных сайта
- **WHEN** модуль `src/data/site.ts` импортируется
- **THEN** siteData содержит: name="Кварта", address="Минск, ул. Короля, 9", phone="+375 (29) 123-45-67" (заглушка), email="hello@example.com" (заглушка), hours={weekday:"8:00–20:00", weekend:"10:00–18:00"}, delivery={freeThreshold:50, day:"пятница", city:"Минск"}, pickup={address:"Минск, ул. Короля, 9"}

### Requirement: Система предоставляет тексты секций

Система SHALL хранить тексты для основных секций сайта на русском языке без пафоса.

#### Scenario: Тексты секций
- **WHEN** модуль `src/data/content.ts` импортируется
- **THEN** content.hero={headline:"Свежий кофе", subheading:"Обжарка в четверг, доставка в пятницу", cta:"Оставить заявку"}; content.about.story="Аня и Дмитрий — бывшие бариста, с 2019 года обжаривают кофе партиями по 5 кг"; content.about.whyFresh.description="Обжарка в четверг → доставка в пятницу → зерно приходит к вам на 1–3 день после обжарки"; content.subscription.description="2×250 г каждый месяц, бесплатная доставка"; content.delivery={title:"Доставка и самовывоз"}

### Requirement: Система предоставляет оптимизированные изображения

Система SHALL предоставлять изображения в формате WebP с указанными размерами для веб-использования.

#### Scenario: Загрузка изображения
- **WHEN** компонент next/image запрашивает файл из `public/images/`
- **THEN** система возвращает изображение в формате WebP с указанными размерами, используя preload для hero

### Requirement: Все изображения имеют alt-тексты на русском

Система SHALL предоставлять изображения с описательными alt-текстами на русском языке.

#### Scenario: Alt-тексты изображений
- **WHEN** компонент изображения рендерится
- **THEN** атрибут alt содержит описание изображения на русском языке (например: "Зёрна кофе крупным планом", "Свежая упаковка кофе", "Кофейные зёрна на деревянной поверхности")

### Requirement: Допущения задокументированы в README

Система SHALL документировать все допущения в README.md.

#### Scenario: Проверка допущений
- **WHEN** разработчик открывает README.md
- **THEN** в разделе "Допущения" отображается список: заглушки телефона и email (фиктивные адреса), обжарка Колумбии medium и Бразилии medium-dark (в ТЗ не указана), самовывоз возможен в любое рабочее время, источники изображений (стоковые, не самой "Кварты", ссылки на Unsplash/Pexels)

### Requirement: Продукты имеют различимые типы

Система SHALL различать типы товаров через дискриминированное объединение Zod.

#### Scenario: Определение типа продукта
- **WHEN** данные продукта парсятся через ProductSchema
- **THEN** поле type определяет схему: для "coffee" нужны roastLevel, notes и optional recommendedFor; для "drip-pack" — quantity; для "subscription" — period и includes
