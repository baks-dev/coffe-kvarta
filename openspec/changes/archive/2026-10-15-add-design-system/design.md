## Goals / Non-Goals

**Goals:**
- Палитра и типографика узнаваемо совпадают с макетом, а не с дефолтами shadcn или Tailwind.
- Секции (04) и форма (05) собираются только из токенов и компонентов этого изменения, без новых цветов.

**Non-Goals:**
- Showcase или Storybook дизайн-системы.
- Полная шкала оттенков (`50…900`) для каждого цвета: токены только семантические.
- Замена заглушки `src/app/page.tsx` (её заменит задача 04).
- Состояние загрузки кнопки (`isLoading`, спиннер): добавляется в задаче 05 вместе с состояниями формы. Здесь достаточно `disabled`.

## Decisions

### 1. Токены: CSS-first `@theme` в `globals.css`, семантические имена

Сырые значения объявляются один раз в `:root` как CSS-переменные, а `@theme inline` публикует их как утилиты Tailwind (`bg-background`, `text-muted-foreground`, `rounded-card`, `shadow-card`, `font-heading`). Имена совпадают с соглашением shadcn (`background`, `foreground`, `card`, `primary`, `accent`, `muted`, `border`, `input`, `ring`, `destructive`), поэтому сгенерированные компоненты подхватывают палитру без правок.

*Альтернативы:* `tailwind.config.ts` из чернового плана в v4 не нужен и дублирует источник. Шкала `primary-50…900` раздувает выбор и провоцирует хардкод оттенков.

Стартовая палитра (контраст посчитан по WCAG 2.1):

| Токен | Значение | Назначение | Контраст |
|---|---|---|---|
| `background` | `#f1ede3` | фон страницы | — |
| `surface` | `#e9e2d5` | полосы-секции («Кто мы», форма) | — |
| `card` | `#f8f5ee` | карточки, поля ввода | — |
| `foreground` | `#1a1814` | заголовки, основной текст | 15,2 на `background` |
| `muted-foreground` | `#625d52` | подписи, вторичный текст | 5,6 / 6,0 / 5,1 на bg / card / surface |
| `primary` / `primary-foreground` | `#1a1814` / `#f8f5ee` | тёмные кнопки | 16,3 |
| `espresso` / `espresso-foreground` | `#1f1a14` / `#f1ede3` | тёмный баннер подписки | 14,8 |
| `accent` / `accent-foreground` | `#cae18a` / `#1a1814` | CTA подписки | 12,4 |
| `border` | `#ddd6c8` | декоративные границы карточек | декоративные, порог 3:1 не требуется |
| `input` | `#8c8574` | граница полей ввода | 3,1 / 3,4 на `background` / `card` |

| `ring-inverse` | `#f1ede3` | кольцо фокуса на `primary` и `espresso` | 14,8 на `espresso` |
| `destructive` | `#a3341f` | ошибки | 6,3 / 5,9 на `card` / `background` |
| `success` | `#3d6b2c` | сообщение об успешной отправке | 5,8 / 5,4 на `card` / `background` |

Отдельный `ring-inverse` нужен, потому что тёмный `ring` на баннере `espresso` даёт 1,03:1 и фокус там не виден.

Вторичный текст из макета (`#727067`) даёт 4,25:1 на фоне и не проходит порог 4.5. Поэтому `muted-foreground` затемнён до `#625d52`; на глаз разница почти не видна. Финальные значения допускается подстроить при реализации, но каждое изменение должно сохранять контраст из спеки.

Радиусы в макете маленькие (карточки и кнопки ≈ 2–4 px). Это одна из черт, которая отличает его от типового AI-лендинга с `rounded-2xl`. Токены: `--radius-sm: 2px`, `--radius-card: 4px`, `--radius-pill: 9999px` (для бейджей при необходимости). Тени почти отсутствуют: `--shadow-card` — одна мягкая тёплая тень на базе `foreground` с низкой альфой. Контейнер: `--container-page: 72rem` (≈1152 px), боковые поля 16 px на мобильных и 32 px от `md`.

### 1a. Типографика и вертикальный ритм

Размеры сняты с макета (1024 px) и пересчитаны на 1440 px. Заголовки масштабируются через `clamp()`, чтобы не нужны были брейкпоинты и H1 помещался на 360 px. Токены объявляются как `--text-*` в `@theme`, тогда Tailwind v4 генерирует утилиты `text-display`, `text-h2` и т. д. вместе с межстрочным интервалом.

| Токен | Размер | Межстрочный | Шрифт |
|---|---|---|---|
| `display` (H1) | `clamp(2.5rem, 1.6rem + 3.6vw, 3.75rem)` | 1.05 | Lora |
| `h2` | `clamp(1.75rem, 1.3rem + 1.8vw, 2.5rem)` | 1.15 | Lora |
| `h3` | `1.25rem` | 1.3 | Golos Text, 600 |
| `body` | `1rem` | 1.6 | Golos Text |
| `small` | `0.875rem` | 1.5 | Golos Text |
| `eyebrow` | `0.75rem`, прописные, трекинг `0.08em` | 1.4 | Golos Text, 500 |

Текст в полях ввода не меньше `1rem`: при меньшем размере iOS Safari увеличивает страницу при фокусе. Вертикальный отступ секций (`--spacing-section`): 64 px на мобильных и 96 px от `md`.

### 1b. Фокус и плавная прокрутка

В `globals.css` задаётся глобальное правило `:focus-visible { outline: 2px solid var(--focus-ring); outline-offset: 2px; }`, где `--focus-ring` по умолчанию равен `ring`. Тёмные поверхности (`bg-primary`, `bg-espresso`) переопределяют `--focus-ring` на `ring-inverse` через утилиту-класс поверхности, поэтому компоненты внутри баннера не знают, где лежат. Сгенерированные shadcn-классы `focus-visible:ring-*` в компонентах заменяются на это общее кольцо, чтобы у фокуса был один источник цвета.

`scroll-behavior: smooth` на `html` включается только внутри `@media (prefers-reduced-motion: no-preference)`.

### 2. Шрифты: Lora (заголовки) + Golos Text (текст)

Оба шрифта подключаются через `next/font/google` с `subsets: ['latin', 'cyrillic']`, `display: 'swap'` и CSS-переменными `--font-heading` / `--font-body`, которые маппятся в `@theme`. Оба вариативные, поэтому не нужно перечислять веса. `next/font` сам хостит файлы, так что запросов к Google при загрузке страницы нет.

- **Lora**: контрастная книжная антиква с полноценной кириллицей, близка к заголовкам макета («Кофе, который приезжает свежим», «Наши сорта»). Тёплая, без журнального глянца Playfair.
- **Golos Text**: гротеск, изначально спроектированный под кириллицу, нейтральный и хорошо читается на телефоне. Inter, напротив, сам по себе маркер «типового» лендинга.

*Альтернативы:* Merriweather из плана (тяжёлая на крупных кеглях, «газетная»), Playfair Display (слишком «премиально», а ТЗ просит без глянца), PT Serif + PT Sans (хорошо, но выглядит как госсайт), Inter, Manrope.

Объявление шрифтов выносится в `src/lib/fonts.ts`, а `layout.tsx` только навешивает переменные на `<html>`.

### 3. Тёмная тема удаляется полностью

Блок `@media (prefers-color-scheme: dark)` удаляется. В `:root` ставится `color-scheme: light`, чтобы нативные контролы (скроллбар, автозаполнение) не темнели. Классы `dark:` в новых компонентах не используются. Такой вариант соответствует бэклогу (`next-themes` не делаем).

### 4. shadcn/ui: только нужные компоненты через CLI

`pnpm dlx shadcn@latest init` (Tailwind v4, без `tailwind.config`, base color выбирается любой и сразу перезаписывается нашими токенами), затем `add button input textarea radio-group label sonner`. Компоненты кладутся в `src/components/ui/`, утилита `cn` — в `src/lib/utils.ts`. После генерации компоненты правятся под макет:

- **Button**: варианты `primary` (тёмная, по умолчанию), `accent` (лайм), `ghost` (текст + стрелка `→`), `outline`. Неиспользуемые `secondary`, `destructive` и `link` удаляются. Сохраняется `asChild` (Radix Slot) для кнопок-ссылок на якоря.
- **Input / Textarea**: фон `card`, граница `input`, `aria-invalid:border-destructive`, фокус через `ring`.
- **RadioGroup** вместо Select для поля «Что интересует». Вариантов всего три (подписка / разовый заказ / вопрос): на телефоне это одно касание вместо двух, и все варианты видны сразу. В макете нарисован select, но ТЗ разрешает «Select/Radio», и радиогруппа лучше подходит для мобильной аудитории из рекламы.
- **Label** нужен для связи подписи с полями (требование спеки).
- **Sonner**: `Toaster` монтируется один раз в `layout.tsx`, цвета берутся из токенов через CSS-переменные компонента. `next-themes`, который shadcn-обёртка Sonner импортирует по умолчанию, из обёртки удаляется, а тема фиксируется как `light`. Позиция `top-center`: трафик в основном мобильный, а `top-right` на узком экране ничем не лучше центра и хуже читается на десктопе.

*Альтернатива:* писать компоненты руками, как в черновом плане. Это быстрее на старте, но без Radix придётся вручную делать навигацию стрелками в радиогруппе и `asChild`. Риск ошибок в a11y выше, чем экономия на зависимостях.

### 5. Логотип: серверный компонент `Logo`

`src/components/logo.tsx` отрисовывает `<a href="#top" aria-label="Кварта, на главную">` с текстом «Кварта» шрифтом заголовков, прописными, с лёгким трекингом (как «КВАРТА» в макете). Прописные задаются через CSS `uppercase`, чтобы в DOM и для скринридера осталось слово «Кварта», а не аббревиатура. Варианты размера: `header` / `footer`.

### 6. Контроль «без хардкода»

Требование спеки проверяется простым поиском (`rg` по `src/components` на `#[0-9a-fA-F]{3,8}\b|rgb\(|hsl\(|oklch\(|-(zinc|gray|neutral|stone|slate)-\d`). Проверка в задаче выполняется вручную. Автоматизацию через ESLint-правило можно добавить в задаче 11/12, но не здесь.

### 7. Отличия от чернового плана `tasks/plans/02-design-system-plan.md`

Источник истины для реализации — этот change. План помечен как заменённый.

| План | Здесь | Почему |
|---|---|---|
| `tailwind.config.ts`, `@tailwind base` | `@theme` в `globals.css` | В проекте Tailwind v4, конфиг v3 игнорируется |
| Палитра `#6B4423`/`#D4A574` + шкалы `50…900` | Семантические токены, снятые с `design.png` | Совпадение с макетом, нет соблазна хардкодить оттенки |
| Inter + Merriweather | Lora + Golos Text | Inter — маркер типового лендинга, Merriweather «газетный» |
| `react-hook-form`, `zod` | Не ставятся | Зависимости формы, задача 05 |
| Компоненты вручную на `red-500`/`gray-300` | shadcn на токенах | Критерий «без хардкода», `aria-invalid`, `asChild`, клавиатура Radix |
| Нативный `Select` | `RadioGroup` | Три варианта, одно касание на телефоне |
| `Logo` как `<h1>` | Ссылка `#top` с `aria-label` | Единственный `h1` принадлежит hero |
| `isLoading` в кнопке | Задача 05 | Нужен вместе с состояниями формы |
| `Toaster position="top-right"` | `top-center` | Мобильная аудитория |
| `scroll-behavior: smooth` безусловно | Только при `prefers-reduced-motion: no-preference` | Доступность |
| Контраст «проверить» | Посчитан для каждой пары | Серый из макета не проходит 4.5:1 |

## Risks / Trade-offs

- [Генератор shadcn пишет цвета в `oklch()` прямо в `globals.css` и может перезаписать наши токены] → запускать `init` до написания токенов, затем заменить сгенерированный блок своей палитрой. Проверить, что CLI не создал `tailwind.config.*`.
- [shadcn CLI не распознаёт Tailwind v4 без `postcss.config.mjs` (у нас Turbopack-loader)] → если `init` падает, создать `components.json` вручную (`tailwind.config: ""`, `css: src/app/globals.css`) и добавлять компоненты через `add`.
- [Лаймовый `accent` с тёмным текстом выглядит кислотно рядом с кремовым] → использовать его точечно: только CTA подписки, как в макете.
- [Два вариативных шрифта с кириллицей увеличивают вес загрузки] → только `latin` + `cyrillic`, `display: swap`, preload только шрифта текста (`preload: false` для Lora, если Lighthouse покажет проблему с LCP в задаче 10).
- [Отказ от select меняет вид формы относительно макета] → зафиксировано как осознанное допущение для README.

## Migration Plan

Изменение затрагивает только стили и новые файлы. Откат — `git revert` коммитов изменения. Заглушка `page.tsx` продолжит работать (её `zinc`/`dark:`-классы просто перестанут реагировать на тёмную тему).

## Open Questions

- Рукописные надписи из макета («Свежая обжарка каждую неделю», «С любовью к хорошему кофе») требуют третьего, рукописного шрифта, а задача ограничивает набор двумя. Варианты: SVG-надписи (без шрифта) или отказ. Решение не меняет токены и компоненты, поэтому откладывается до задачи 04.
