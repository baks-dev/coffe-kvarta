# Proposal

## Why

В репозитории пока нет кода приложения: только ТЗ, исследование и декомпозиция на задачи (`tasks/01–13`). Все последующие задачи (дизайн-система, секции лендинга, форма, `/api/lead`, тесты, CI/деплой) опираются на единый каркас. Нужен воспроизводимый проект, который с первого коммита собирается и проходит линтеры. Иначе ошибки инфраструктуры всплывут позже, когда до дедлайна (19 октября, 18:00 МСК) останется меньше времени на их разбор.

## What Changes

- Каркас приложения на Next.js (App Router) + TypeScript в режиме `strict` + Tailwind CSS, менеджер пакетов pnpm.
- Абсолютные импорты через алиас `@/*` → `src/*`.
- Базовая структура исходников: `src/app`, `src/components`, `src/lib`, `src/data`.
- Единые команды разработчика: `dev`, `build`, `start`, `lint`, `typecheck`, `format`, `format:check`.
- Prettier, согласованный с ESLint (форматирование не конфликтует с правилами линтера).
- Метаданные репозитория: `LICENSE` (MIT), `.env.example` без секретов.
- `.github/dependabot.yml`: еженедельные обновления npm-зависимостей.
- Каркас фиксируется отдельными коммитами по шагам (требование ТЗ).

Вне рамок изменения: CI-пайплайн GitHub Actions и деплой на Vercel (задача 12), тестовый раннер (задача 11), дизайн-токены и шрифты (задача 02), pre-commit-хуки.

## Capabilities

### New Capabilities
- `dev-workflow`: контракт рабочего окружения разработчика: какие команды есть в проекте и что они гарантируют (сборка, линт, проверка типов, форматирование), разрешение импортов `@/`, обязательная структура исходников, метаданные репозитория (лицензия, шаблон переменных окружения) и автоматическое отслеживание обновлений зависимостей.

## Impact

- **Код**: новые файлы в корне (`package.json`, `pnpm-lock.yaml`, `tsconfig.json`, `next.config.ts`, `eslint.config.mjs`, `postcss.config.mjs`, `.prettierrc.json`, `.prettierignore`, `LICENSE`, `.env.example`), каталоги `src/` и `public/`, `.github/dependabot.yml`.
- **Зависимости**: `next`, `react`, `react-dom`, `tailwindcss`, `@tailwindcss/postcss`, `typescript`, `@types/*`, `eslint`, `eslint-config-next`, `prettier`, `eslint-config-prettier`.
- **Документация**: в `README.md` появится раздел о запуске и командах.
- **Последующие задачи**: 02–13 используют эти команды и структуру. Задача 12 (CI) вызывает `lint`, `typecheck` и `build` в том виде, в каком их определяет эта спецификация.
